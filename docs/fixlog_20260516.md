# GoWAF v1.1.9 修复日志

**发布日期**: 2026-05-16  
**版本**: v1.1.9  
**基于版本**: v1.1.8

## 修复列表

### 1. 观察模式不生效

**问题**: 开启观察模式后，攻击请求仍被拦截而非仅记录。

**根因**: 三层逻辑冲突：
- `detectSequential` 中观察模式检测结果不加入 results
- `detectWithDetectors` 中 SQL 语法分析和敏感数据检测同样过滤观察模式结果
- `checkAttackDetection` 不区分观察/拦截，直接全部拦截

**修复**:
- 检测层始终返回完整结果（不再按观察模式过滤）
- 拦截层 `checkAttackDetection` 根据 `IsObservationMode()` 分别处理：观察模式仅记录不拦截，拦截模式返回 403
- 文件: `internal/proxy/detect.go`, `internal/detector/manager.go`

### 2. 智能拦截权重超过 1.0

**问题**: 智能拦截模块中各检测器权重之和超过 1.0，导致限流计算异常。

**根因**: `adjustWeights()` 只增不减且没有归一化，权重值会累积超过 1.0。

**修复**:
- 添加 `normalizeWeights()` 方法，在权重调整后自动归一化到 [0, 1] 范围
- 文件: `internal/ratelimit/engine.go`

### 3. 检测器规则数显示为 0

**问题**: 6 个检测器（path_traversal, header_injection, sensitive_data, file_upload, error_leak, request_smuggling）在界面上显示规则数为 0，尽管它们有硬编码的检测逻辑。

**根因**: 这 6 个检测器有硬编码规则但未注册到数据库 `detection_rules` 表，前端从数据库读取规则数因此显示 0。

**修复**:
- 为 6 个缺失检测器添加数据库内置规则（与硬编码逻辑一一对应）
- 文件: `internal/detector/config.go`

### 4. 内置规则自动修复

**问题**: 已有数据库重启后，新增的内置规则不会自动补齐，需要手动删库重建。

**根因**: `initBuiltinRules()` 对每个检测器类型都有 `if count == 0` 前置检查，只在该类型无规则时才插入。已有数据库中如果缺少某个新增类型的规则，不会补齐。

**修复**:
- 去掉所有 `count == 0` 前置检查，改为始终执行 `INSERT OR IGNORE`
- `detection_rules` 表有 `UNIQUE(detector_type, pattern)` 约束，`INSERT OR IGNORE` 是幂等的，已有规则会被忽略，缺失规则会被自动补齐
- 同时去掉 `NewConfigManager` 中的二次验证逻辑
- 文件: `internal/detector/config.go`
