## 修复列表

### 1. [严重] 所有规则禁用后检测器仍使用旧规则

**问题**: 当某检测器的所有规则都被禁用（enabled=false）后，ReloadRules 发现过滤后 patterns 为空直接 return，不清空检测器内存中的规则。旧规则仍然生效，拦截照常触发。

**修复**: 去掉 `if len(patterns) == 0 { return }` 保护，允许 setPatterns 接受空切片。所有规则禁用后检测器 patterns 被清空，不再命中任何规则。

### 2. [严重] request_smugging 拼写错误导致请求走私检测器规则无法加载

**问题**: `initBuiltinRules` 中使用 `"request_smugging"` 插入内置规则，但其他所有地方（initDefaultConfig、Manager、前端）使用 `"request_smuggling"`。导致：
- ListRules("request_smuggling") 找不到任何规则，热加载后请求走私检测器无规则
- 每次启动重复插入一批 `request_smugging` 的错误记录

**修复**: 
- initBuiltinRules 中 `"request_smugging"` → `"request_smuggling"`
- migrateLegacyDetectorNames 中添加 detection_rules 表的迁移：`UPDATE detection_rules SET detector_type = 'request_smuggling' WHERE detector_type = 'request_smugging'`

### 3. [中等] WAFProxy 接口缺少 GetDetectorManager 方法定义

**修复**: 在 WAFProxy 接口中添加 `GetDetectorManager() *detector.Manager`

### 4. [中等] API 层 ReloadRules 失败时静默忽略

**问题**: ToggleRule/AddCustomRule/RemoveRule 后调用 ListRules 或 GetRuleByID 失败时，仍返回成功响应。用户以为操作成功但规则实际未生效。

**修复**: ListRules/GetRuleByID 失败时返回 jsonError 响应
