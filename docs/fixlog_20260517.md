## 一、项目结构重构

### 重构概述

将 `internal/` 下33个扁平包重组为4层架构（domain/infra/cert/pkg），消除反向依赖、合并碎片包、补充包文档，提升模块化、可维护性和可扩展性。

### 重构后目录结构

```
internal/
├── domain/                      # 业务领域层
│   ├── proxy/                   #   核心代理域（proxy + pathbodylimit）
│   ├── security/                #   安全检测域（detector, rules, ratelimit, limiter, bot, vpatch, dlprule）
│   ├── gateway/                 #   Web接口域（handler, middleware, static, templates, model）
│   ├── auxiliary/               #   辅助功能域（blockpage, reqheader, respheader, sessionsafe, compliance, masker）
│   └── proxyconfig/             #   代理配置管理（跨域共享）
├── infra/                       # 基础设施层
│   ├── config/                  #   配置管理域（config, configversion）
│   ├── storage/                 #   数据存储域（database, logdb, metrics, stats）
│   ├── logger/                  #   异步日志系统
│   ├── event/                   #   事件缓冲
│   ├── notify/                  #   通知系统
│   └── interfaces.go            #   统一接口定义（Logger/Metrics/Event/Config）
├── cert/                        # 证书与更新域（acme, geoipupdater）
├── pkg/xutil/                   # 通用工具域（合并netutil+timeutil）
├── apischema/                   # API接口定义（含配置回调解耦）
├── backend/                     # 后端服务管理
└── testutil/                    # 测试基础设施（dbutil, httputil, assertx）
```

### 依赖方向规则

| 规则 | 说明 |
|------|------|
| `domain/` → `infra/` | 允许：业务依赖基础设施 |
| `infra/` → `domain/` | **禁止**：基础设施不可反向依赖业务 |
| `pkg/` → 任何内部包 | **禁止**：工具包零外部依赖 |

### 重构阶段详情

| 阶段 | 风险 | 内容 |
|------|------|------|
| 阶段1 | 低 | 工具包合并(netutil+timeutil→xutil)、反向依赖修复(config→middleware通过apischema回调解耦)、event迁移infra、31个doc.go补充 |
| 阶段2 | 中 | 23个包迁移到功能域分组(security/auxiliary/infra/cert/pkg) |
| 阶段3 | 高 | web/proxy/pathbodylimit/proxyconfig迁移到domain/下对应域 |
| 阶段4 | 低-中 | testutil基础设施创建、infra接口层定义(Logger/Metrics/Event/Config) |

## 二、Bug修复

### 1. [严重] 拦截日志查询时区不一致导致数据不显示

**问题**: `intercept_events` 表中 `time` 字段以 UTC 时间写入（`time.Now().UTC().Format(...)`），但 `APIIntercepts`、`APIEvents`、`APITopIPs`、`APITopPaths`、`APIRuleHits` 等接口的查询时间使用本地时间 `time.Now()`，导致 UTC+8 时区下查询窗口与写入数据存在8小时偏移，历史拦截数据无法被正确查询到。

**影响**: 拦截日志页面显示"暂无数据"，仪表盘统计数据为空。

**修复**: `internal/domain/gateway/handler/dashboard.go` 中5处查询时间改为 UTC：
- `time.Now().AddDate(0, 0, -7)` → `time.Now().UTC().AddDate(0, 0, -7)`
- `time.Now()` → `time.Now().UTC()`

**涉及函数**: `APIDashboard`、`APIEvents`、`APIIntercepts`、`APITopIPs`、`APITopPaths`、`APIRuleHits`

### 2. [严重] logDB未注入logger导致数据库日志功能失效

**问题**: `cmd/waf/main.go` 中 `logger.InitWithRotationAndDB()` 在 logDB 创建之前调用，且第4个参数传了 `nil`，导致 `useDB = false`，日志从不写入 logdb 数据库。依赖 logdb 数据库查询的 API（如 `GetLogsAggregate`、`GetLogsExport`、`GetLogsTimeSeries`）均返回空数据。

**修复**: 
- 在 `internal/infra/logger/logger.go` 中添加 `SetDB(db *logdb.LogDB)` 方法
- 在 `main.go` 中 logDB 创建后调用 `logger.SetDB(logDB)`

### 3. [中等] 拦截日志降级逻辑缺陷

**问题**: `APIIntercepts` 中当 metrics 数据库查询成功但返回0条记录时（`len(allEvents) == 0`），代码错误地降级到内存环形缓冲（容量仅200条，重启后为空），而非直接返回空分页结果。

**修复**: 仅当 `GetEvents` 返回 error 时降级到内存数据；查询成功但无数据时直接返回空分页响应。

### 4. [低] pageSize上限与前端请求不匹配

**问题**: 前端 `intercepts_table.js` 请求 `page_size=10000`，但后端 `APIIntercepts` 限制 `pageSize > 1000` 时重置为100，导致分页和总数不匹配。

**修复**: pageSize 上限从 1000 调整为 10000。

### 5. [低] 管理界面端口被Hyper-V保留导致启动失败

**问题**: Windows Hyper-V 保留端口范围 9085-9184（包含默认端口 9090），导致 `bind()` 被拒绝，服务启动失败。

**修复**: `config.yaml` 中管理界面端口从 `0.0.0.0:9090` 改为 `0.0.0.0:8090`。
